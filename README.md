# Alphabet Battle Cards（ABC）

アルファベットで戦う 2 人用カードゲームの、ブラウザ版です。ゲームクリエイター甲子園 2026 応募作品。
カラーアスキーアートで描いた盤面に、Three.js でカードを裏返す演出を重ねています。

- CPU 対戦 / 2 人対戦（同じ画面で交代）/ チュートリアル / デック編集 / コレクション（トロフィーカード）/ ルール表示
- ルールエンジンは画面から切り離した純粋な関数（`src/engine/`）。同じ seed なら同じ結果
- カード・ルール・文言・色・CPU の重みは、すべて `src/data/*.json` で編集できる

## 遊び方（コマンド 1 つ）

```bash
abc-play
```

依存のインストール（初回だけ）→ 開発サーバの起動 → ブラウザで http://localhost:5210 を開く、までを 1 回で行います。止めるときは Ctrl+C。
`abc-play` は `~/.local/bin/abc-play → play.sh` のシンボリックリンクです。別の環境で作るときは:

```bash
ln -sf "$(pwd)/play.sh" ~/.local/bin/abc-play
```

## 開発用のコマンド

Node 22 以上（`.nvmrc` は 24）。`play.sh` はシェル既定の node が古ければ nvm から探します。

```bash
npm install
npm run dev          # http://localhost:5210
npm test             # ルールエンジンの受け入れテスト（node --test）
npm run sim -- --games 200            # CPU 同士の対戦を回して勝率を集計
npm run sim -- --games 200 --no-first-auto   # 先攻 1 ターン目の自動ダメージなし
npm run tier -- --games 2000 --out tier.json   # カードごとの強さ（そのカードを入れたデックの勝率・使用回数）を集計
npm run build        # 型チェック + dist/ へ出力（相対パスなので静的ホスティングにそのまま置ける）
```

`?tutorial` を付けて開くと、チュートリアルから始まります。

## 編集できるデータ（`src/data/`）

| ファイル | 中身 |
|---|---|
| `config.json` | ルールの数値（撃破数・サブ倍率・進化ターン・ストレージ上限など）と、仕様の [未決定] 項目の切り替え |
| `units.json` | 26 文字の HP / ATK（小文字の値）・技のコストと効果（効果の部品 `ops` の組み合わせ） |
| `attributes.json` | 属性ごとの大文字の固有ルール（HP / ATK ボーナス・ターン終了時の回復） |
| `symbols.json` | 記号 28 種類の効果 |
| `decks.json` | デックのプリセット |
| `text.json` | 画面の文言・ログ・ルール説明 |
| `tutorial.json` | チュートリアルの台本（デックの積み込み順と手順） |
| `glyphs.json` | カードの大きな文字（5×5 ドット） |
| `theme.json` | 色 |
| `ai.json` | CPU の評価関数の重み |
| `fx.json` | 演出の強さ（画面の揺れ・フラッシュ・火花の量・ワイプの速さ） |
| `trophies.json` | トロフィーカードの条件・名前・ランクと、ごほうびの裏面デザイン |
| `audio.json` | BGM・効果音のファイル名と音量 |

効果の部品（`ops` の `op`）は `src/engine/effects.ts` にあります:
`damage` `heal` `guard` `halfDamage` `reflect` `protectStorage` `seal` `needle` `costUp` `autoMinus` `oppSubMult` `storageCap`
`autoBonus` `subMult` `extraSkill` `extraSymbol` `extraStorage` `costReduce` `boostStorage` `evoShift` `draw` `search` `recover`
`storageToHand` `kick` `yank` `peekDiscard` `cycle` `reshuffleHand` `warp` `swapSub` `swapHandSub` `swapHp` `gamble` `revive` `cleanse`

## 演出

- 攻撃: カードが相手に向かって突っ込み、当たると画面が揺れて文字の火花が散る（ダメージが大きいほど強く揺れる。25 以上は大きな数字）
- 撃破: 画面が白く光り、大きく揺れて、カードが回転しながらトラッシュへ
- 進化: 属性の色で光り、カードが 3 回転して大文字に。技・記号・お釣りもそれぞれ光る
- 画面の切り替え: 文字が流れるワイプで切り替わる。タイトルはロゴがグリッチしながら現れ、メニューが順に入ってくる
- 看板: YOUR TURN / CPU TURN / ○○ FIRST / K.O. / EVOLVE / MATCH POINT はアスキーアートの大きな文字（背景は透過）

### 盛り上げの演出（パチンコ風）

- **LETHAL**: 自分のターンに、ターンを終えれば自動ダメージで相手のメインを倒せる見込みになると、相手のメインが赤く脈打ち「LETHAL」の札が付く。ターン終了ボタンも点滅する。ターン終了を押したら消える（トドメの攻撃が目立つように）
- **MATCH POINT**: どちらかがあと 1 撃破で勝ちになると看板が出て、撃破数の表示が点滅し続ける
- **WILD!**: 0（ワイルド）を引くと金色に光る
- **トロフィーのルーレット**: トロフィーを取ると、スロットのようにカードが入れ替わってから止まり、裏返って登場する。クリックで飛ばせる
- **先攻決め**: 盤面が暗くなって「WHO FIRST?」。大きなカードが回ってゆっくり止まり、光って「YOU FIRST」などを見せる
- LETHAL の表示は `fx.json` の `lethal` で切り替えられる

### タイトルの遊び

- 背景で舞っているカードをクリックすると、手前に跳ねて別のカードに裏返る
- ロゴの ABC をクリックするとグリッチして、一瞬ほかの 3 文字に化ける。10 回目は全部のカードが裏返る
- キーボードで `a` `b` `c` と打つと、全部のカードがいっせいに裏返る

## トロフィーカード

条件を満たすと、トロフィーカード（全 35 枚、BRONZE / SILVER / GOLD / PLATINUM）が手に入ります。
対戦の内容で取れるもの（記号でトドメ・Needle や反射で撃破・一撃必殺・ダブル撃破・ストレート・ゾロ目・大当たり など）と、
通算の記録で取れるもの（勝利数・連勝・26 文字の技をすべて使う・28 種類の記号をすべて使う など）があります。
対戦のあとに 3D で裏返って登場し、タイトルの「コレクション」で眺められます（クリックで回る）。
一部のトロフィーはごほうびとして**カードの裏面デザイン**が付き、コレクション画面で切り替えられます。
条件は `trophies.json`、記録はブラウザの localStorage（`abc.prefs.v1` の `progress`）にあります。
カードはすべて最初から使えます（解放の仕組みは入れていない）。

## 結果を X で共有

決着の画面の「X で共有」を押すと、X の投稿画面が文面入りで開きます（投稿するかは自分で決める）。
文面は「Alphabet Battle Cards（ABC）で CPU に勝ちました！ / デック「スターター」（A M F H P C S）/ 撃破 5 - 2・24 ターン」のような形で、`text.json` の `share` で変えられます。

## フォント

- 英数字: JetBrains Mono（同梱、SIL OFL 1.1）
- 日本語: **廻想体 ネクストUP（B）**（[もじワク研究](https://moji-waku.com/kaiso/)、フリーフォント・商用可・クレジット不要）
- 廻想体が無いときの代わり: UDEV Gothic 35（同梱、SIL OFL 1.1。ゲームで使う文字だけに絞ってある）

廻想体の[使用許容範囲](https://moji-waku.com/mj_work_license/)は、Web フォントとしてサーバに置くことは可、無断の再配布・フォントデータの改変は不可です。
そのため**フォントのファイルはリポジトリに入れていません**（`.gitignore` 済み）。作者が配布している Web フォント（`kaiso_up_web.zip`）を、手を加えずにそのまま使います。
`abc-play` は、ファイルが無ければ最初に作者のサイトから取ってきます。手動で取るときは:

```bash
npm run font:kaiso
```

UDEV Gothic の文字を足すとき（文言に新しい漢字を足して、廻想体が無い環境で別のフォントになったとき）は `npm run font:jp`（uv が必要）。

## 紹介用の素材（ゲームクリエイター甲子園 2026）

`promo/` で、実際のゲーム画面からサムネイルと紹介動画を作れます（ヘッドレスの Chrome で自動で遊んで撮る）。
先に `abc-play` で開発サーバを動かしておきます。出力は `promo/out/`（git には入れない）。

```bash
cd promo && npm install
npm run thumbs   # 1920×1080 の PNG を 5 枚（タイトル・対戦・進化・トロフィー・撃破）
npm run video    # 1920×1080・30fps・H.264 の紹介動画 abc-intro.mp4（台本の 11 シーン＋締めのロゴ・約 2 分、音は無音のトラック。テロップは video.mjs の SCRIPT、締めは ending.html）
```

撮影のときは、見せ場が出るように盤面を整えています（進化の直前にする、相手の HP を減らしておく など）。

## 仕様書から決めたこと・未決定の扱い

仕様書の [未決定] は勝手に決めず、`config.json` の設定にしています（既定値は仕様の現行ルール）。

| 項目 | 設定 | 既定 |
|---|---|---|
| 先攻・後攻の決め方 | `firstPlayer`（random / p1 / p2） | random（公開のあとに決める） |
| 先攻 1 ターン目の自動ダメージ | `firstTurnAutoDamage` | true |
| ハンドのユニットをサブの空きに自動で置くか | `autoPlaceHandUnits`（ターン開始のドローのあと） | false |
| 同名の文字・記号の上限 | `deck.maxSameUnit` / `maxSameSymbol` | 1 |

仕様に書かれていなかった細部は、次のように実装しました。

- **お釣りあり**（仕様書 5.1 から変更、`config.json` の `change`。false で仕様書どおりのお釣りなしに戻る）
  - 余りは、支払いに使った中でいちばん大きい数字カードに「残り」として残る。使い切ったカードだけトラッシュへ
  - 例: コスト 3 を 9 で払う → 9 は「残り 6」でストレージに残る。続けてコスト 4 → 「残り 2」
  - 0 はワイルドカードのまま（お釣りなしでトラッシュ）。`#` の +2 は先に使う
  - 残りのあるカードがストレージを離れる（`=` でハンドに戻す、Kick される、トラッシュへ）と元の値に戻る
- 支払いは「合計がコスト以上（または 0 を含む）」に加えて、**余分なカードを含まない組み合わせ**だけを受け付ける（どの 1 枚を抜いても足りなくなる）。画面では使い切るカードが少ない組み合わせを自動で選ぶ
- 「`'`（コスト -3）」は、このターン最初に使う技 1 回だけに効く（`costReduceOnce`）
- 「`*`（サブ倍率 1）」と相手の「`/`（サブ倍率 0）」が重なったら、自分のターンに使った `*` を優先
- 「`.`」で終わらせる妨害は 封じ・コスト増加・Needle（`cleanseKinds`）。`-` と `/` は含めない
- ハンドに戻ったユニット（`[ ]`）は在籍ターンだけ 0 に戻す（`returnToHand` で進化・HP のリセットも選べる）
- Drain の回復量は、与えたダメージではなく効果の値（10 / 20）
- 対象が無い技や記号も使える（空振り）。Kick は相手が `( )` で守っていれば無効
- 技・記号で引いたユニットはハンドへ（サブに入るのはターン開始時と開始時のドローだけ）

## シミュレーション（参考）

`npm run sim -- --games 250`（CPU 同士、プリセット 5 種の総当たり、お釣りあり）:

- 先攻の勝率 54%、平均 29 ターン、未決着 0
- プリセット別の勝率: ダイアゴナル 83% / スターター 59% / ミックス 46% / トリックスター 37% / フォートレス 25%

### Zap（Z）の調整

ティア表（`npm run tier`、ランダムなデック同士で 6,000 戦）で、Z を入れたデックの勝率が 74% と突出していた。
Zap だけを弱くしても 62% より下がらず（コスト 8・20 / 30 でも 61.8%）、原因は Zap のダメージと Z の高い ATK（12、大文字で 27）の組み合わせだった。
24 通りを 3,000 戦ずつ比べて、**コスト 6 → 8、ダメージ 25 / 50 → 20 / 40、ATK 12 → 8** にした（Z の勝率 56.8%、M の 58.3% に次ぐ 2 位）。
ATK 8 は「頻度の低い文字は ATK 12」という仕様書の基準値の式から外れる。

| コスト | ダメージ | ATK | Z の勝率 |
|---|---|---|---|
| 6 | 25 / 50 | 12 | 72.8%（元） |
| 8 | 20 / 40 | 12 | 64.1% |
| 8 | 20 / 30 | 12 | 61.8% |
| 8 | 20 / 30 | 10 | 59.8% |
| 7 | 20 / 35 | 8 | 55.0% |
| **8** | **20 / 40** | **8** | **56.0%（6,000 戦では 56.8%）** |

### Tough（T）の調整

お釣りありにしたら、進化した T の Tough（ガード40・コスト 5）が毎ターン使えるようになり、フォートレス同士で決着しない対戦が出た（60 戦中 16 戦）。
大文字のガードを **40 → 25** に下げた（コスト 5 と小文字のガード20 はそのまま）。候補をシミュレーションで比べた結果（フォートレス同士 60 戦）:

| コスト | ガード（小→大） | 未決着 | 平均ターン |
|---|---|---|---|
| 5 | 20 → 40（元） | 16 | 209 |
| 5 | 20 → 30 | 1 | 148 |
| 6 | 20 → 30 | 0 | 154 |
| 7 | 20 → 40 | 0 | 159 |
| **5** | **20 → 25** | **0** | **142** |

フォートレス同士はそれでも 130 ターン前後と長い。ガードを全部 0 にしても 119 ターンかかるので、原因はガードではなく、
デックの組み方（ATK の低い Orthogonal・Cure の回復・封じや ! - / の記号）にある。

仕様書 13.2 の「Diagonal が強い」傾向は、技と記号を入れても残っています。
